## Requirement

"Obscure feedback of authentication information."

## Objectives

[a] authentication information is obscured during the authentication process.

## Sufficient

- **Default operating system masking of password entry**, showing dots or asterisks in place of typed characters, satisfies the objective on its own without any further configuration. [a]
- **Leaving an optional reveal control enabled next to a password field.** The objective concerns the feedback a system shows by default, not whether a user can deliberately choose to view their own entry, so a field that masks by default is accepted even when a reveal option sits beside it. [a]
- **A layered mix of controls where no single one covers every system**: a written procedure telling staff not to trigger a reveal control while someone else can see the screen, a device management setting that turns off the reveal feature on managed endpoints, a password manager that never displays a pasted password's characters, and single sign-on that cuts down how often a password gets typed in the first place. Each layer reaches systems or situations the others do not, and whatever remains uncovered is handled through the written procedure. [a]
- **A written policy statement committing to obscure authentication feedback**, paired with screenshots from each type of system in scope, such as operating system login screens, network device management consoles, and a single sign-on portal, each showing masked entry. [a]

## Insufficient

- **A login prompt that displays typed password characters in clear text, with no masking and no brief-then-obscured display, on a system where hiding the entry is technically possible.** The Assessment Guide's discussion ties this objective directly to preventing someone nearby from reading the characters as they are typed, so a plaintext display defeats the objective outright. [a]

## Over-engineering

- **Disabling a password field's optional reveal feature everywhere it exists.** Practitioner consensus treats this as unnecessary, since the objective is already satisfied by the default masked state; removing the reveal option only adds a usability cost, such as more mistyped passwords that staff cannot double-check and more account lockouts for support staff to resolve. [a]
- **Building a custom obscuring mechanism for a system that already masks entry by default.** Where the platform's default behavior already satisfies the objective, layering anything further on top meets no additional objective language.

## Edge cases

- **Whether an optional reveal control undermines this requirement is resolved in practice: it does not.** The objective concerns the default feedback shown during entry, and public authentication guidance on this exact topic recommends offering a way to display a memorized secret for usability rather than requiring dots or asterisks with no exception.
- **Some applications, particularly certain mobile and third-party apps, offer no setting to turn off a built-in reveal feature.** Where no technical control is available, the layered approach falls back to written procedure for that system, and that fallback is treated as sufficient. [a]
- **Small-display devices are held to a different balance than a desktop or notebook screen.** The Assessment Guide's discussion allows a brief on-screen display of characters before they are obscured on a small device, weighing the risk of someone reading the screen against the higher risk of typing errors on a cramped keyboard. [a]

## Evidence examples

- **Screenshots from each system type in scope showing masked password entry**, covering operating systems, network device management interfaces, and a single sign-on portal. [a]
- **A written policy statement committing to obscure authentication feedback during the authentication process.** [a]
- **Device management configuration disabling the password reveal feature**, for an organization that chooses to turn it off on managed endpoints. [a]

## Related requirements

- **3.5.10** protects the password itself in storage and in transit; this requirement protects the password at the moment of entry, when it is most exposed to anyone nearby.
- **3.5.2** governs the authentication event this requirement's masking behavior occurs within; obscuring feedback is one property of how that event is presented to the user, not a separate authentication step.
