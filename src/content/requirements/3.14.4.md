## Requirement

"Update malicious code protection mechanisms when new releases are available."

## Objectives

[a] malicious code protection mechanisms are updated when new releases are available.

## Sufficient

- **Current protection agent versions on workstations and servers**, treated as base-level proof that update mechanisms are working. [a]
- **For platforms that update automatically, pairing a vendor knowledge base article describing the automatic update behavior with a screenshot of the enabled configuration**, in place of a manual update log the automation does not produce. [a]
- **Configuring anti-malware software to check for and apply signature updates daily.** Assessment Guide example ties this to how quickly malware definitions change, making frequent automatic updates the expected behavior. [a]

## Insufficient

No documented position beyond the Assessment Guide; see confidence.

## Over-engineering

No documented position beyond the Assessment Guide; see confidence.

## Edge cases

- **Automatic-update platforms make it hard to produce proof of each individual update event.** Practitioner consensus resolves this by proving the auto-update capability itself is enabled and functioning, typically through vendor documentation plus a configuration screenshot, rather than logging every update as it happens. [a]

## Evidence examples

- **Screenshots of current endpoint agent and signature versions.** [a]
- **Vendor documentation describing the automatic definition-update mechanism.** [a]
- **A screenshot or export showing the auto-update setting enabled** in the management console. [a]

## Related requirements

- **3.14.2** establishes the designated locations and baseline protection that this requirement keeps current.
- **3.14.5** depends on protection mechanisms being up to date so periodic and real-time scans detect current threats.
