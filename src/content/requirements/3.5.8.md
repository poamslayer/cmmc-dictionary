## Requirement

"Prohibit password reuse for a specified number of generations."

## Objectives

[a] the number of generations during which a password cannot be reused is specified; and
[b] reuse of passwords is prohibited during the specified number of generations.

## Sufficient

- **A specific number of prior password generations defined as off-limits, with technical enforcement that rejects a reuse attempt and requires a new password instead.** Assessment Guide example describes exactly this behavior: a user who tries to reuse a password within the defined count receives an error and must enter a different one. [a][b]
- **A restriction that does not extend to temporary passwords.** Assessment Guide discussion treats password-history rules as applying to permanent passwords, separate from the one-time temporary password used at initial logon. [b]

## Insufficient

No documented position beyond the Assessment Guide; see confidence.

## Over-engineering

No documented position beyond the Assessment Guide; see confidence.

## Edge cases

- **How many generations counts as sufficient is left to the organization to define.** Assessment Guide discussion frames this as a question the organization answers for itself, not a fixed count set by the standard. [a]

## Evidence examples

- **Directory or system configuration showing the enforced password-history count.** [a][b]
- **Documentation or policy stating the defined number of password generations that cannot be reused.** [a]

## Related requirements

- **3.5.7** governs the shape of each new password (complexity and character change); this requirement governs how many prior passwords stay off-limits when a new one is chosen.
- **3.5.9** carves out the one exception to ordinary password rules, the temporary password used at first logon, which this requirement's history count does not need to cover.
