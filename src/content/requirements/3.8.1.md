## Requirement

"Protect (i.e., physically control and securely store) system media containing CUI, both paper and digital."

## Objectives

[a] paper media containing CUI is physically controlled;
[b] digital media containing CUI is physically controlled;
[c] paper media containing CUI is securely stored; and
[d] digital media containing CUI is securely stored.

## Sufficient

- **A locked cabinet or drawer set aside for hardcopy CUI in each office, paired with a locked rack or server room for the equipment holding digital CUI.** Splitting the program this way, one control for paper containers and a separate one for digital equipment spaces, lets a single mechanism satisfy the physical-control and secure-storage objectives for each media type without one program having to cover both. [a][c] on the paper side, [b][d] on the digital side.
- **Treating the NIST SP 800-171 glossary entry for "media" as the first reference when scope is unclear, and only falling back to a broader NIST SP 800-53 definition where the narrower one is silent.** Practitioner consensus favors the 800-171 wording, which names magnetic tapes, optical disks, magnetic disks, integrated-circuit memory chips, and printouts, because that is the definition the assessment objectives were written against. [a][b]
- **Standardizing on one encrypted removable media line as the only authorized option, then logging its issuance and return.** A single check-out and check-in process for that media satisfies both the physical-control and secure-storage objectives for digital media in one program, rather than running them as separate efforts. [b][d]
- **An inventory log paired with a checkout procedure for CUI-bearing media**, matching the Assessment Guide's own worked example of a labeled drive stored in a locked drawer, logged on an inventory, and checked out and returned under a documented process. [b][d]

## Insufficient

No documented position beyond the Assessment Guide; see confidence.

## Over-engineering

No documented position beyond the Assessment Guide; see confidence.

## Edge cases

- **Whether this requirement reaches workstation and server hard drives the same way it reaches paper documents and removable devices.** Practitioner consensus treats 3.8.1 as primarily concerned with removable media and hardcopy, and treats ongoing protection of CUI already at rest on fixed drives as the more specific job of 3.13.16. The NIST SP 800-171 glossary definition of media, which lists magnetic disks and integrated-circuit memory chips alongside removable formats, supports reading fixed storage as within the definition's scope even where day-to-day implementation work routes to that other requirement instead.
- **Where the line sits between this requirement and 3.8.2 for the same physical asset.** Practitioners commonly describe 3.8.1 as the office-level storage program (locked cabinets, desks) and 3.8.2 as the room-level or rack-level access program (server rooms, equipment racks), with a single issuance process for authorized encrypted removable media able to satisfy pieces of both at once.

## Evidence examples

- **Locked cabinet or drawer** used for paper CUI storage. [a][c]
- **Server room or rack door lock** covering equipment that holds digital CUI. [b][d]
- **Media inventory log** recording checkout and return of CUI-bearing devices, as in the Assessment Guide worked example. [b][d]
- **Written procedure** describing who may check out media and how the checkout is recorded. [a][b]
- **Issuance record** documenting a standardized, encrypted removable media line assigned to specific users. [b][d]

## Related requirements

- **3.8.2** narrows this requirement's access half into a data-access question: who is authorized to read the CUI once the media itself is physically secured.
- **3.8.5** picks up where physical storage ends, covering accountability for the same media once it leaves a controlled area for transport.
- **3.13.16** governs protection of CUI at rest on fixed storage more specifically than this requirement's physical-control and storage focus.
