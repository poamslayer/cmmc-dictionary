## Requirement

"Perform periodic scans of the information system and real-time scans of files from external sources as files are downloaded, opened, or executed."

## Objectives

[a] the frequency for malicious code scans is defined;
[b] malicious code scans are performed with the defined frequency; and
[c] real-time malicious code scans of files from external sources as files are downloaded, opened, or executed are performed.

## Sufficient

- **A weekly scheduled scan cadence**, accepted as satisfying the defined-frequency objectives in a completed assessment. [a][b]
- **Real-time scanning applied where CUI-related files first arrive**, such as inbound email attachments, satisfying the real-time objective without also requiring a scan-on-open trigger for every file type. [c]
- **A documented, consistently applied scan depth that matches written policy.** Since the requirement does not specify scan thoroughness, practitioner consensus treats a faster scan type as acceptable as long as policy says what is actually done and practice matches it. [b]
- **Gateway or firewall antivirus with deep packet inspection**, satisfying the real-time objective for systems that can only receive downloads by routing through that gateway. [c]
- **Endpoint detection and response tooling that scans continuously in transit, on access, and on execution**, documented as an equivalent approach where the platform lacks a traditional scheduled-scan feature, supported by vendor documentation explaining why continuous coverage is comparable to periodic scanning. [b][c]
- **Scoping scans to the locations named in policy**, rather than to every possible asset in the environment, treated as an accepted reading of the requirement's scope. [a][b]

## Insufficient

- **Running only real-time protection with no periodic scan component.** The requirement is read as two separate obligations rather than one satisfied by the other, so objectives [a] and [b] remain unaddressed without a distinct periodic scan. [a][b]
- **A mobile platform's web-protection-only feature**, which does not provide real-time file scanning and does not by itself satisfy the real-time objective for that device class. [c]
- **A gateway-based antivirus solution with a coverage gap**, wherever a download path can bypass the gateway through another device or connection. [c]

## Over-engineering

- **Running a deep, resource-intensive scan across an entire system when real-time protection already covers file transit, access, and execution.** This adds load without a corresponding gain toward the objective it is meant to satisfy. [b]
- **Extending scanning to opening a read-only file with no execution.** This reaches past the objective's core concern, which centers on files being downloaded or executed rather than merely viewed. [c]
- **Running a full interval scan against a very large shared repository where a complete pass is impractical**, when the same content is already covered by real-time protection at the point of access. [b]

## Edge cases

- **Mobile devices accessing CUI by email are treated differently from traditional endpoints.** Enrollment, containerization, patch management, and jailbreak detection through a mobile device management platform are accepted in place of conventional file scanning for that device class.
- **Whether a designated access point can stand in as the scan location for a large specialized storage environment**, avoiding a full scan of the underlying repository, is treated as workable when the designated location is documented in policy, though this has not been uniformly confirmed; the outcome depends on the assessor.
- **Where an endpoint detection platform has no periodic-scan feature at all**, vendor documentation explaining why continuous protection is equivalent is the accepted substitute, but how much documentation is enough varies; the outcome depends on the assessor.

## Evidence examples

- **Written policy defining the scan frequency and scan type used.** [a]
- **Scan configuration screenshots or exported settings** showing the scheduled interval. [b]
- **Scan logs or reports** showing execution at the defined interval. [b]
- **Real-time protection configuration** showing scanning on download and execution. [c]
- **Email security configuration** showing inbound attachment scanning. [c]
- **Mobile device management compliance policy configuration** for devices accessing CUI by email. [c]
- **Vendor documentation supporting an endpoint detection platform's continuous-coverage claim.** [b][c]
- **A network diagram showing all download paths routed through a gateway antivirus solution.** [c]
