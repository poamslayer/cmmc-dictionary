## Requirement

"Route remote access via managed access control points."

## Objectives

- [a] managed access control points are identified and implemented; and
- [b] remote access is routed through managed network access control points.

## Sufficient

- **Point to the cloud identity provider's conditional access policy** as the managed access control point for a cloud-only or SaaS-only environment, even where a fair argument exists that reaching an organization's own SaaS tenant may not squarely fit the classic remote-access picture. [a][b]
- **Borrow characteristics from federal trusted-connection guidance** to describe what makes a point "managed": encrypted traffic inspection, a policy enforcement point that logs connection activity, integration with a central log platform and an approved identity provider, anti-malware protection, and intrusion detection. [a]
- **Combine a firewall VPN for on-premises access with identity-provider conditional access for cloud resources** in a hybrid environment, so every path in funnels through one managed point per environment type. [a][b]

## Insufficient

No documented position beyond the Assessment Guide; see confidence.

## Over-engineering

- **Forcing a traditional VPN funnel onto a cloud-only architecture** when the cloud provider's own conditional access mechanism already serves as the managed access control point. Legacy on-premises routing spends effort a cloud-native environment does not need. [a][b]

## Edge cases

- Whether reaching an organization's own government-authorized cloud tenant counts as remote access to an "organizational system," or instead counts as access to an external system already covered by a separate federal authorization, has no settled answer; one line of reasoning treats the tenant as external and outside this requirement's literal reach, another treats any internet-based access as remote regardless, and the outcome depends on the assessor. The safer path in practice is to show the access control point exists and is enforced either way, so the applicability argument does not have to be won.
- Whether an outside party's remote management of one endpoint, rather than of the organization's information system as a whole, triggers this requirement is treated by some as outside its reach, on the reasoning that it is remote control of a single component rather than remote access to the organizational system.
- How to handle an external collaborator reaching a shared file site for legitimate business work, and how specific remote-support tools should be classified, were both raised without a settled resolution.

## Evidence examples

- Network diagram marking the managed access control point or points. [a]
- Conditional access policy export from the identity provider used for cloud resources. [a][b]
- Firewall or VPN concentrator configuration showing inbound remote traffic terminating at one location. [b]

## Related requirements

- 3.1.12 defines and monitors the sessions this requirement routes.
- 3.1.13 requires cryptographic protection on the sessions passing through the access control point.
- 3.1.15 governs what privileged commands and security-relevant access those sessions may carry once through the control point.
