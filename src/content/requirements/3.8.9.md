## Requirement

"Protect the confidentiality of backup CUI at storage locations."

## Objectives

[a] the confidentiality of backup CUI is protected at storage locations.

## Sufficient

- **Using an authorized cloud storage and collaboration platform, inside a government-community cloud tenant, for CUI backups.** This satisfies the requirement for the portion of backup activity the provider itself controls. [a]
- **Full inheritance from a cloud provider, where all CUI storage and backup activity is handled entirely by a properly authorized provider**, documented through the provider's own responsibility matrix describing what it protects. [a]
- **On-premises protection combining physical security, such as a locked server room with access control, with logical security, such as authenticated, logged, and monitored access, plus validated encryption on the endpoints that reach the data.** Accepted as sufficient for backup confidentiality under the current standard revision. [a]
- **A cloud-only backup architecture**, where all CUI and its backups sit inside a government-community cloud tenant's native storage and collaboration tools with backups controlled by the platform itself. Described as working well in an assessment specifically when this is the organization's only backup path. [a]

## Insufficient

- **Claiming full inheritance from a cloud environment without being able to demonstrate what is actually inherited and how.** A bare assertion that everything is covered because the organization uses an authorized cloud tenant does not on its own satisfy the requirement; the organization still has to show its own understanding of the inherited protections. [a]
- **Relying on a storage location without the required authorization, regardless of what encryption is applied there.** Current guidance calls for the backup storage location itself to carry the appropriate authorization, not merely for the data on it to be encrypted. [a]
- **Claiming cloud inheritance while CUI also exists in locations the organization has not accounted for.** Inheritance only covers the backup activity actually confined to the authorized provider; unaccounted-for CUI elsewhere breaks the claim. [a]

## Over-engineering

- **Adding storage-layer encryption on top of already-adequate physical and logical controls for an on-premises backup location, where the current standard revision does not require it.** Given a properly secured server room and endpoint access already using validated encryption with logging and monitoring, an additional encryption layer at the storage device itself is not required under the current revision, though this position may not hold once the standard moves to its next revision. [a]

## Edge cases

- **Relying on a single cloud storage platform as the only location for all CUI, with no local copies retained.** Inheritance is achievable in that specific circumstance, but the organization still needs to confirm, and be able to demonstrate, that CUI is not stored anywhere else before claiming it. [a]
- **Native backup features inside a government-community cloud tenant that may not be fully available in every such environment.** Organizations should verify what backup capability actually exists in their specific tenant rather than assuming full parity with the commercial version of the same platform.
- **Whether on-premises encryption requirements for backup storage will change when the standard moves to its next revision.** This is presently unresolved; organizations relying on the current revision's physical-and-logical-controls allowance should track this as the standard transitions rather than assume it carries forward unchanged.

## Evidence examples

- **Responsibility matrix** from the cloud storage provider documenting the backup protections it provides. [a]
- **Authorization documentation** for the backup storage provider. [a]
- **Policy or procedure** stating backup storage locations and how confidentiality is protected at each. [a]
- **SSP language** describing inheritance of this requirement from an authorized cloud provider. [a]
- **Physical security documentation, access logs, and encryption verification** for an on-premises backup storage location. [a]

## Related requirements

- **3.8.3** governs eventual sanitization or destruction of backup media once it is retired, after this requirement's protection period ends.
- **3.8.6** applies the same cryptographic-or-physical-safeguard logic to CUI on digital media while it is in transit to a backup location.
- **3.12.4** documents in the SSP which party protects backup confidentiality and how, often by citing a provider's responsibility matrix as the answer.
